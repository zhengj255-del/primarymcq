## 3. Conventions you must not break

**Ids are permanent.** Every record's `id` is `<topic slug>__<code>`. Attempts, SRS state
and user edits are keyed on it in both apps. **Changing an id destroys study progress.**
Never renumber, never re-slug, never "tidy" an id.

**The provenance line is load-bearing.** Every question the model touched carries one line
at the top of its `reason`, before a blank line, in one of these forms:

- `Explanation supplied by the tracker's GPT audit (MODEL, prescribed-text grounded), DATE — …`
- `Recalled key corrected, and explained, by the tracker's GPT audit (MODEL, prescribed-text grounded), DATE — …`
- `Left unkeyed: the tracker's GPT audit could not settle this question (ambiguous), DATE — …`
- `Answer and explanation supplied by the tracker's GPT audit (MODEL, prescribed-text grounded), DATE — …`

Do not strip, reword, or duplicate these. They are the only thing telling a candidate
mid-question that the answer is a model's and not an examiner's. The tracker's
`corpus/bake-overrides.mjs` detects them by the literal substring `the tracker's GPT audit`
to stay idempotent — change the wording and the next refresh will stack a second line.

**`disputed: true` means "do not serve as settled".** The site parks these on the Disputes
page instead of serving them into a sitting.

## 5. How to refresh again

The tracker owns the adjudication; this repo only ever receives the result.

```sh
# in this repo, after replacing corpus/additions-2025-2026-recalls.json
node corpus/merge-additions.mjs corpus/additions-2025-2026-recalls.json server/data/mcqs.json
npm run check && npm test
```

`merge-additions.mjs` is idempotent by `id`: it replaces records whose id exists and appends
the rest. Both apps re-ingest at the next boot when the file's hash changes; attempts, SRS
state and edits survive because they are keyed by id.

`server/__tests__/noAi.test.ts` must stay green. It fails the build if any identifier from the
removed AI machinery (`openai`, `gpt`, `mcq_audit`, `textbook`, `renton`, …) appears under
`server/`, `shared/` or `client/src`, or if any file imports from outside this repository.
`server/data` and `corpus/` are exempt from that scan — which is why the provenance lines,
which contain "GPT", are allowed to live in the question text but must never migrate into code.

## 6. Provenance block in the JSON

`corpus/additions-2025-2026-recalls.json` carries a `baked` object recording the refresh:

```json
{
  "from": "renton-tracker MCQ audit (server/mcqAudit.ts -> server/ai/mcqTriage.ts), applied per question id",
  "model": "gpt-5.6-sol",
  "date": "2026-09-07",
  "exportedAt": "2026-09-07T07:12:44.275Z",
  "overridesFolded": 298,
  "keyedFromRecall": 258,
  "keyed": 513,
  "answersSuppliedByAudit": 255,
  "disputedByVerdict": 1,
  "note": "Answers marked in each reason are the audit's, grounded in the prescribed texts. No examiner has confirmed them."
}
```

Its `sources[]` entries also carry `keyedFromRecall` (what the recallers supplied — sticky,
set on the first bake) and `keyed` (the current total), so the human/model split stays
readable after any number of refreshes.
